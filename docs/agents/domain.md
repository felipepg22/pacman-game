# Domain Docs

This project has one context: the root `CONTEXT.md` glossary and `docs/adr/` decisions.

Before exploring, read the glossary and ADRs relevant to the task.
Use canonical glossary terms in requirements, issue titles, hypotheses, and tests.
Surface conflicts with an accepted ADR before proposing a different decision.
If a domain document is absent, proceed without scaffolding it; domain-modeling creates documents when terms or decisions are resolved.
